# 전처리: AI-Hub 라벨링 JSON을 설비별 표로 변환하고 결측, 이상값 정리

## 문제

원본은 AI-Hub 전력설비 라벨링 데이터로, 설비 1대의 측정값이 JSON 파일 5개에 나뉘어 있다. 파일마다 센서값은 같고 라벨만 다르며, 측정값이 세로형(시각, 항목명, 값)으로 저장되어 있어 바로 분석하기 어렵다. 그래서 설비 1대를 "시각 × 측정항목" 표 1개로 바꾸는 작업을 먼저 했다.

## 처리 흐름

```text
원본 JSON (설비당 5개)
→ 첫 파일에서 센서값 읽기
→ (시각, 항목명) 중복 행 제거
→ 세로형 → 가로형 (시각 × 측정항목 35개)
→ 나머지 파일에서 라벨 5개를 컬럼으로 붙이기
→ 시간순 정렬
→ 설비별 parquet 저장 + meta.csv
→ (공유용) csv.gz 사본
```

코드: [scripts/01_preprocess.py](../scripts/01_preprocess.py), [scripts/01b_export_csv.py](../scripts/01b_export_csv.py)

## 원본 구조

```text
<원본 폴더>/
+-- Training/ , Validation/
    +-- 1.펌프_일반모터/ , 2.공조설비/
        +-- 1.기동패턴/
        |   +-- 1.전류평균/0.Combined/*.json
        |   +-- 2.유효전력평균/0.Combined/*.json
        +-- 2.SOH진단/
            +-- 1.역률평균/0.Combined/*.json
            +-- 2.전류고조파평균/0.Combined/*.json
            +-- 3.전압고조파평균/0.Combined/*.json
```

파일명의 `LabelledData_<번호>_` 부분이 설비 번호이고, 이 번호로 5개 파일을 묶었다.

## 단계별 처리

| 단계 | 한 일 | 이유 |
| --- | --- | --- |
| 센서값 읽기 | 5개 파일 중 첫 파일에서만 센서값을 읽었다 | 5개 파일의 센서값이 같아서 한 번만 읽으면 된다 |
| 중복 제거 | (TIMESTAMP, ITEM_NAME)이 같은 행은 첫 행만 남겼다 | 중복이 있으면 가로형 변환(pivot)이 실패한다 |
| 가로형 변환 | ITEM_NAME을 컬럼으로, ITEM_VALUE를 값으로 바꿨다 | 시각마다 한 행이어야 분석과 모델 입력이 쉽다 |
| 라벨 붙이기 | 파일별 LABEL_NAME을 시각 기준으로 컬럼 5개에 붙였다 | 기동 상태와 SOH 진단 결과를 한 표에서 보기 위해서 |
| 정렬 | TIMESTAMP를 날짜형으로 바꾸고 시간순으로 정렬했다 | 시계열 분석 전제 |
| 저장 | `data/processed/<split>/<설비종류>/<번호>.parquet` | 설비 단위로 나눠야 메모리에 부담이 적다 |
| 설비 정보 | 업체, 설비 용량, 전압 등 18개 항목 + 행 수, 기간을 `meta.csv`에 모았다 | 설비를 고르거나 그룹으로 나눌 때 쓴다 |
| 실패 기록 | 읽기에 실패한 설비는 `errors.csv`에 남기고 넘어갔다 | 압축 해제가 덜 된 파일 때문에 전체가 멈추지 않게 |

이미 변환한 설비는 건너뛰기 때문에, 중간에 멈춰도 다시 실행하면 이어서 진행된다.

## 2차 전처리

[EDA](eda.md)에서 찾은 결측, 측정 상한값, 계측 오류 구간을 정리했다. 행을 지우면 시계열이 끊기므로, 잘못된 값만 결측으로 바꾸고 무엇을 했는지 표시 컬럼 4개로 남겼다.

코드: [scripts/03_clean.py](../scripts/03_clean.py)

```text
설비별 parquet (data/processed)
→ 시각을 분 단위로 내리고 1분 격자로 다시 맞추기 (빈 분은 행 추가)
→ 측정 상한값, 전압 튐, 주파수 이상을 결측으로
→ 5분 이하 결측만 보간 (측정값은 선형, 라벨은 앞 값)
→ 전원 꺼짐 표시
→ 전원 꺼짐 95% 이상인 파일 제외
→ data/cleaned/<split>/<설비종류>/<번호>.parquet + clean_log.csv
```

### 기준

| 단계 | 기준 | 이유 |
| --- | --- | --- |
| 1분 격자 | 시각을 분 단위로 내리고, 같은 분에 2행이면 먼저 들어온 값 사용 | 측정 초가 설비마다 달랐고(:00, :34 등), 2분 간격 1,840곳은 대부분 수집 지연이었다 |
| 측정 상한값 | 상별 전류가 512 또는 4095 이상이면 그 값과 전류평균을 결측 | 기동 순간 돌입전류가 센서 상한에서 잘린 값이라 실제 크기를 알 수 없다 |
| 전압 튐 | 상전압(평균 포함) 500 V, 선간전압(평균 포함) 800 V 초과면 그 행의 전압 컬럼 전체를 결측 | 정격 최대가 440 V인데 1분씩 940~999 V가 찍혔다 |
| 주파수 이상 | 전원이 들어온 상태에서 55~65 Hz 밖이면 그 행의 측정값 전체를 결측 | 548번 Training 1/19~1/28은 167 Hz, 97 V로 찍히면서 유효전력이 0에 가까웠다 |
| 보간 | 연속 5분 이하 결측만 선형 보간, 라벨은 앞 값으로 채움 | 기동 상태가 몇 분 안에는 잘 바뀌지 않는다. 더 긴 끊김을 채우면 없는 운전 패턴을 만들게 된다 |
| 전원 꺼짐 | 상전압평균 50 V 미만이면 `flag_power_off=1` | 299~301번은 꺼진 동안 7 V, 20 Hz 잔류값이 찍혀서 0 기준으로는 못 잡았다 |
| 파일 제외 | 전원 꺼짐 95% 이상인 파일 제외 | Validation 80번은 기간 전체가 꺼져 있었다 |

음수 유효전력과 음수 역률, 정지(Stop) 구간, 누적전력량은 값을 바꾸지 않았다. 음수는 특정 설비에서 일관되게 나와 측정 방향 문제로 봤고, 정지 구간은 기동 패턴 분석에 필요하다. 누적전력량은 설비마다 기준값이 달라 그대로 쓰지 말고 차분해서 쓴다.

스케일링은 여기서 하지 않았다. Training 기간 값으로만 기준을 잡아야 Validation 정보가 새지 않고, 설비별로 할지 전체로 할지는 모델에 따라 달라서 모델 단계에서 정한다.

### 추가된 컬럼

| 컬럼 | 뜻 |
| --- | --- |
| flag_missing | 원본에 없던 분이라 새로 넣은 행 |
| flag_clip | 측정 상한값이 있어 전류를 결측으로 바꾼 행 |
| flag_invalid | 전압 튐 또는 주파수 이상으로 값을 결측으로 바꾼 행 |
| flag_power_off | 전원이 꺼진 행 (상전압평균 50 V 미만) |

### 결과

| 항목 | 내용 |
| --- | --- |
| 파일 | 210개 중 209개 (Validation 80번 제외) |
| 행 수 | 3,939,038행 → 4,008,999행 (빈 분 77,172행 추가) |
| 결측으로 바꾼 값 | 측정 상한값 10행, 전압 튐 86행, 주파수 이상 13,821행 |
| 보간 후 남은 결측 행 | 95,967행 (2.4%). 대부분 1시간 넘게 끊긴 73곳과 548번 계측 오류 구간 |
| 전원 꺼짐 표시 | 184,092행 |

보간으로 채운 행은 140행뿐이었다. 남은 결측은 대부분 긴 끊김이라, 모델 입력을 만들 때 결측이 들어간 윈도우를 빼는 방식으로 처리한다.

## 아직 하지 않은 것

- 스케일링은 모델 단계에서 Training 기준으로 한다.
- 음수 유효전력 설비(363, 406, 467, 548번)를 부호 반전할지 정하지 않았다.
- 누적전력량 차분 컬럼은 특징 추출 단계에서 만든다.

## 실행 방법

```bash
pip install -r requirements.txt
python scripts/01_preprocess.py --raw-dir "<원본 데이터 폴더>"
python scripts/01b_export_csv.py
python scripts/02_eda.py
python scripts/03_clean.py
```

원본 폴더는 `--raw-dir` 대신 환경변수 `THESIS_RAW_DIR`로 지정해도 된다. 지정하지 않으면 `data/raw`를 쓴다.

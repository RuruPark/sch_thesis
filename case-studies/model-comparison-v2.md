# 새 주 모델 기준 비교 다시 맞추기: 펌프+6종 학습에서도 트리 모델이 규칙·LR보다 높고, 데이터 추가 효과는 10/30/60분 모두 +0.17로 유의함

## 문제

주 모델이 "펌프만 학습, 특징 148개"(처음 보는 펌프 설비 PR-AUC 0.470)에서 "펌프 + 6종 학습, 보강 특징 167개"(0.638)로 바뀌었다. 그런데 규칙, Logistic Regression, 예측 구간 10/60분 비교는 모두 옛 기준에서 나온 숫자였다. 논문 표에 두 기준이 섞이면 "새 조건에서도 순위가 같은가"에 답할 수 없다. 또 묶음별 PR-AUC가 0.445~0.871로 흔들려, 0.01~0.17 차이가 설비 구성과 관계없이 유지되는지도 숫자로 보여야 했다.

코드: [scripts/17_extra_facilities.py](../scripts/17_extra_facilities.py) `--compare --save-scores`, [scripts/19_unit_bootstrap.py](../scripts/19_unit_bootstrap.py), [scripts/20_threshold_recal.py](../scripts/20_threshold_recal.py)

## 분석 흐름

```text
data/features_v2 (보강 특징 167개, 펌프 + 6종)
→ 08번과 같은 펌프 5묶음 배정 (seed 0)
→ 규칙 / LightGBM 펌프만 / LightGBM·LR·RF 펌프+6종 학습
→ 처음 보는 펌프 설비 점수를 행 단위로 저장
→ 설비 단위 부트스트랩 신뢰구간, 새 설비 임계값 재보정
→ 예측 구간 10/60분 반복
```

## 목표와 측정 지표

- 새 주 모델 조건에서도 LightGBM이 규칙과 LR보다 높은가
- 다른 설비종류를 더한 효과(펌프만 → 펌프+6종)가 설비 구성과 관계없이 유지되는가
- 새 설비의 처음 며칠로 임계값만 다시 맞추면 오경보가 줄어드는가
- 지표 정의는 [docs/metrics.md](../docs/metrics.md)

## 실험

### 실험 1. 같은 조건의 모델 비교

LR과 RF는 06·07번과 같은 설정이다. 펌프+6종 학습 행이 220만 개가 넘어, LR·RF는 양성은 전부 두고 음성만 줄여 150만 행으로 맞춘 뒤 가중치로 되돌렸다. 임계값은 모든 모델을 펌프 학습 설비 뒤 20%에서 F1 최대로 골랐다.

### 실험 2. 설비 단위 부트스트랩

처음 보는 펌프 설비 60대를 복원 추출로 1,000번 다시 뽑아 PR-AUC 95% 구간을 냈다. 같은 표본에서 두 모델의 차이도 계산했다. 같은 설비의 1분 행은 서로 강하게 이어져 있어, 행 단위로 뽑으면 구간이 지나치게 좁아진다.

### 실험 3. 새 설비 임계값 재보정

모델은 그대로 두고, 설비마다 Validation 앞 N일로 임계값만 다시 맞췄다. 지표는 모든 방식을 보정 기간 뒤에서만 계산했다.

- 라벨 사용 F1: 보정 기간에 이상 발생이 있으면 그 기간 F1 최대 지점으로 다시 고름
- 점수 분위 상한: 보정 기간 점수의 상위 5/2/1%만 경보가 되도록 임계값 하한을 올림. 라벨이 필요 없음

## 결과

### 모델 비교 (처음 보는 펌프 설비 PR-AUC, 95% 구간)

| 모델 | 10분 | 30분 | 60분 |
| --- | --- | --- | --- |
| 규칙 | 0.188 (0.110~0.323) | 0.327 (0.223~0.483) | 0.439 (0.315~0.593) |
| Logistic Regression 펌프+6종 | 0.241 (0.155~0.391) | 0.410 (0.288~0.600) | 0.526 (0.396~0.698) |
| LightGBM 펌프만 | 0.351 (0.194~0.546) | 0.472 (0.357~0.716) | 0.551 (0.402~0.793) |
| **LightGBM 펌프+6종** | **0.522** (0.338~0.687) | **0.638** (0.487~0.772) | **0.722** (0.580~0.836) |
| Random Forest 펌프+6종 | 0.505 (0.352~0.678) | 0.645 (0.491~0.777) | 0.721 (0.576~0.849) |

| 30분, 대기 1분 | F1 | 사건 재현율 | 하루 오경보 |
| --- | ---: | ---: | ---: |
| 규칙 | 0.402 | 83.9% | 19.3 |
| Logistic Regression 펌프+6종 | 0.517 | 87.3% | 10.6 |
| LightGBM 펌프만 | 0.489 | 89.6% | 9.7 |
| **LightGBM 펌프+6종** | **0.584** | 83.1% | **5.5** |
| Random Forest 펌프+6종 | 0.556 | 90.4% | 6.5 |

- 30분 LightGBM 펌프+6종은 0.638로 [feature-extension.md](feature-extension.md)의 seed 0 값과 같았다.
- 펌프만 학습했던 옛 LR(0.396)과 비교해 LR은 데이터를 늘려도 0.410으로 거의 그대로였다. 데이터 추가 효과는 트리 모델에서만 컸다.

### 짝 차이 (B − A, 95% 구간)

| 비교 | 10분 | 30분 | 60분 |
| --- | --- | --- | --- |
| 펌프만 → 펌프+6종 (LightGBM) | +0.171 (0.045~0.269) | +0.167 (0.007~0.275) | +0.170 (0.014~0.291) |
| 규칙 → LightGBM 펌프+6종 | +0.335 (0.217~0.421) | +0.312 (0.211~0.400) | +0.283 (0.175~0.372) |
| LR → LightGBM 펌프+6종 | +0.282 (0.139~0.400) | +0.228 (0.087~0.341) | +0.195 (0.077~0.296) |
| LightGBM → RF (펌프+6종) | −0.017 (−0.052~0.035) | +0.007 (−0.034~0.044) | −0.001 (−0.039~0.037) |
| 규칙 → LightGBM 펌프만 | +0.164 (0.063~0.271) | +0.145 (0.025~0.326) | +0.113 (−0.062~0.319) |

- 다른 설비종류를 더한 효과는 세 예측 구간 모두 +0.17이고 구간이 0을 포함하지 않았다. 다만 30분 하한이 0.007로, 효과 크기는 설비 구성에 따라 크게 달라진다.
- LightGBM과 RF는 세 구간 모두 구간이 0을 포함해 차이가 없다.
- 60분에서는 펌프만 학습한 LightGBM이 규칙보다 낫다고 말할 수 없었다(구간 −0.062~0.319). 데이터를 더해야 규칙과의 차이가 확실해졌다.

### 임계값 재보정 (LightGBM 펌프+6종, 30분)

| 보정 기간 | 평가 설비 | 방식 | 대기 | 사건 재현율 | 하루 오경보 |
| --- | ---: | --- | ---: | ---: | ---: |
| 1일 | 46 | 기존 | 1분 | 83.1% | 5.9 |
| 1일 | 46 | 기존 | 2분 | 71.8% | 2.6 |
| 1일 | 46 | 점수 95% 분위 상한 | 1분 | 55.4% | 1.6 |
| 1일 | 46 | 점수 95% 분위 상한 | 2분 | 42.7% | 0.5 |
| 1일 | 46 | 라벨 사용 F1 | 1분 | 90.6% | 7.6 |
| 3일 | 26 | 기존 | 1분 | 82.8% | 1.8 |
| 3일 | 26 | 점수 95% 분위 상한 | 1분 | 62.1% | 0.2 |
| 3일 | 26 | 라벨 사용 F1 | 1분 | 93.1% | 5.8 |

- 점수 분위 상한은 오경보를 크게 줄였지만 사건 재현율도 같이 떨어졌다. 1일 보정 95% 상한(55.4%, 1.6회)은 기존 임계값에 대기 3분을 둔 것(57.9%, 1.4회, [feature-extension.md](feature-extension.md))과 거의 같은 자리였다.
- 라벨 사용 F1은 오경보가 오히려 늘었다. 하루치 사건이 몇 건뿐이라 임계값이 그 사건에 맞춰 낮게 잡혔다.
- Validation은 설비당 최대 6일(중앙값 2.7일)이라 7일 보정은 평가할 행이 없었다. 1일과 3일은 평가 설비가 달라 서로 비교하지 않는다.

## 판단

- 주 모델은 LightGBM 펌프+6종으로 유지한다. RF와 성능 차이가 없고, 30분 기준 F1과 오경보에서 조금 앞서며, 이미 SHAP·경보 분석을 이 모델로 했다.
- 논문의 모델 선택 근거는 "LightGBM이 RF보다 높다"가 아니라 "트리 앙상블이 규칙·LR보다 확실히 높고, 그중 LightGBM을 썼다"로 쓴다.
- 논문 비교표는 이 문서의 숫자로 바꾼다. 옛 기준(펌프만 학습) 수치는 "데이터 추가 전" 비교로만 남긴다.
- "다른 설비종류를 함께 학습하면 처음 보는 설비 PR-AUC가 +0.17 오른다"를 신뢰구간과 함께 핵심 결과로 쓴다.
- 새 설비 임계값 재보정은 쓰지 않는다. 경보 대기 시간을 바꾸는 것 이상의 이득이 없었다.

## Trade-off

| 선택 | 대안 | 고른 이유 | 포기한 점 |
| --- | --- | --- | --- |
| 설비 단위 부트스트랩 | 행 단위 부트스트랩, 묶음별 t검정 | 같은 설비 행끼리의 상관을 반영하고, 묶음 5개보다 표본이 많음 | 평가 설비가 60대뿐이라 구간이 넓다 |
| LR·RF는 150만 행으로 줄여 학습 | 전체 행 | 16GB 메모리에서 float64 사본을 만들면 부족함 | 두 모델은 LightGBM보다 적은 음성을 봤다 |
| 라벨 없는 분위 상한 | 라벨 사용 재보정만 | 새 설비 처음 며칠에는 이상 발생이 거의 없음 | 임계값을 올리기만 해서 놓친 사건을 되찾지 못한다 |
